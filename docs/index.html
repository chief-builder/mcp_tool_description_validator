Three Signals, Clearly Separated

A strict project recommendation is not automatically an MCP violation. Every result carries its authority and the report keeps protocol compliance distinct from the active policy threshold.

S

Specification

Finalized MCP requirements such as tool shape, JSON Schema, metadata, and x-mcp-header.

G

Governance

Configurable defensive policy such as bounded inputs, annotations, pagination, and output controls.

H

Heuristics

Name- and text-based signals for model comprehension that benefit from human review.

Rule Coverage

The validator treats MCP tool quality as a cross-functional problem: protocol shape, security boundaries, naming, model comprehension, and runtime behavior hints all matter.

SCH

Schema

Required fields, JSON Schema validity, object-shaped inputs, and explicit required arrays.

NAM

Naming

MCP name grammar, uniqueness, consistent parameter casing, descriptive verbs, and tool-set grouping.

SEC

Security

Bounded inputs, URL and path constraints, sensitive defaults, safe headers, and context-aware heuristics.

LLM

LLM Fit

Actionable descriptions, parameter guidance, workflow cues, and ambiguity checks.

BP

Practice

Annotations, output schemas, parameter count, nesting depth, and usability guidance.

Use It Three Ways

Run it locally as a CLI, embed it in TypeScript, or start a small HTTP service. File and live-server inputs use the same rule engine.

1

CLI Gate

Validate JSON or YAML files and fail CI with --ci when effective-profile errors are present.

2

Library API

Call validate, validateFile, or validateServer from a release workflow.

3

HTTP Service

Run mcp-validate serve and post definitions plus validated configuration to /validate.
