Rule Coverage

The validator treats MCP tool quality as a cross-functional problem: protocol shape, security boundaries, naming, model comprehension, and runtime behavior hints all matter.

SCH

Schema

Required fields, JSON Schema validity, object-shaped inputs, and explicit required arrays.

NAM

Naming

Kebab-case tools, camelCase parameters, descriptive verbs, and predictable identifiers.

SEC

Security

Bounded strings, bounded arrays, URL and file path constraints, and sensitive defaults.

LLM

LLM Fit

Actionable descriptions, parameter guidance, workflow cues, and ambiguity checks.

BP

Practice

Annotations, output schemas, parameter count, nesting depth, and usability guidance.

Use It Three Ways

Run it locally as a CLI, embed it in another TypeScript tool, or start a small HTTP service for internal validation workflows.

1

CLI Gate

Validate JSON or YAML files and fail CI with `--ci` when errors are present.

2

Library API

Call `validate`, `validateFile`, or `validateServer` from a custom release workflow.

3

HTTP Service

Run `mcp-validate serve` and post tool definitions to `/validate`.
